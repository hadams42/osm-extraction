Executive Summary

This engagement delivers a repeatable, restartable pipeline that converts the global OSM PBF into administrative boundary GeoJSON outputs, then transforms those outputs into an ArcGIS Pro file geodatabase (FGDB) and publishes separate ArcGIS Online hosted feature layers suitable for web mapping, analysis, and downstream application integration. The work is organized into two phases: (1) Infrastructure setup and GIS processing, and (2) 30 days of post-delivery support.

Scope Overview

In Scope

  • AWS infrastructure as code for a high-memory processing host, storage, and permissions
  • Planet OSM → GeoJSON boundary extraction split by country and administrative level
  • ArcGIS Pro workstation on AWS (GPU) install and configuration for client use to execute Phases 4-6 (remote access enabled)
  • Handoff package enabling client execution of GeoJSON normalization, FGDB build, attribution, QA/QC, and AGOL publishing (Phases 4-6)

Out of Scope (unless added by change order)

  • Custom web app development beyond layer publication and basic usability checks
  • Ongoing monthly operations beyond the defined 30-day support window
  • Third-party licensing, ArcGIS Pro licensing, or ArcGIS Online credit purchases

Client Responsibilities (Phases 4-6)

Phases 4-6 are executed by the client's team (with contractor support during the 30-day support window as needed):
  • AWS ArcGIS Pro workstation usage: Client uses the AWS graphics compute workstation with ArcGIS Pro to perform Phases 4-6 (including ArcGIS licensing/sign-in and access control)
  • Phase 4: Normalize and stage GeoJSON for ArcGIS Pro (including chunking/merge as needed)
  • Phase 5: ArcGIS Pro FGDB build + NUTS/LAU attribution (OSM refs → Wikidata crosswalk → spatial fallback)
  • Phase 6: QA/QC, dissolve, publish hosted feature layers to ArcGIS Online, and smoke tests

Important Assumptions

The client will provide access to an AWS account for provisioning and an ArcGIS environment (ArcGIS Pro and ArcGIS Online organization) for publishing. A single reference vintage year for admin boundaries will be selected and used consistently for attribution and validation. Hosting and compute charges (including the AWS GPU workstation used for ArcGIS Pro) will be billed to the client at cost. Important Note: Once this AWS infrastructure is created, the client will easily be able to leverage it for other projects.

High-Level Implementation Plan

Phase 1

Confirm inputs, naming, and reference datasets

5-8 hrs

Lock decisions that prevent rework later (file conventions, vintage, publishing titles, and field model).

  • Define input/output folder conventions and AGOL item naming
  • Select admin boundary vintage year and obtain reference boundaries
  • Confirm minimum field schema (IDs, names, country, provenance, confidence)
Phase 2

Infrastructure setup (AWS, security, cost controls)

6-8 hrs

Provision a repeatable AWS environment for OSM processing and a client-accessible ArcGIS Pro workstation.

  • Terraform for VPC/Security Group, EC2 (memory-optimized), EBS, S3, IAM role/policies
  • Provision an AWS graphics compute (GPU) workstation (Windows) for ArcGIS Pro client use
  • Install and configure ArcGIS Pro on the GPU workstation; enable secure remote access for the client
  • Bootstrap the processing host (osmium, Python deps, mount/format data volume) and validate S3 access
  • Operational guardrails: logging paths, lifecycle cleanup, and teardown guidance
Phase 3

Global OSM → GeoJSON boundary pipeline (restartable)

8-14 hrs

Implement a checkpointed pipeline that can resume across interruptions and continuously sync outputs.

  • Upload planet-latest.osm.pbf to S3; download to the processing host’s data volume
  • Filter administrative boundary relations and extract country polygons
  • Per-country extraction and per-level exports (GeoJSONSeq .geojsonl)
  • Orchestrator with checkpoint.json, logging, retries, and periodic S3 sync of results
  • Teardown/runbook: sync final outputs, then deprovision AWS resources to avoid ongoing charges
Phase 4

Normalize & stage GeoJSON for processing by ArcGIS Pro

Client-performed

Convert GeoJSONSeq to ArcGIS-importable FeatureCollections and optionally chunk/merge for large countries.

  • Use the AWS ArcGIS Pro GPU workstation to run the client processing steps
  • .geojsonl → .geojson FeatureCollection conversion
  • Optional chunking for very large files and repeatable merge strategy
  • Documented staging layout for import runs
Phase 5

ArcGIS Pro FGDB build + hybrid NUTS/LAU attribution

Client-performed

Create clean, queryable feature classes per level and assign official codes with confidence tracking.

  • ArcGIS Pro import via JSON To Features into FGDB (one feature class per level)
  • Attribution priority: OSM refs (ref:nuts/ref:lau) → Wikidata crosswalk → overlap match
  • Record method and match score; flag low-confidence matches for review
Phase 6

QA/QC, dissolve, publish to ArcGIS Online, and smoke tests

Client-performed

Finalize geometry and publish hosted layers with consistent metadata and baseline performance checks.

  • Repair geometry, multipart handling, deduplication, dissolve by code, compute area/perimeter
  • Validate coverage and counts vs expected and generate match statistics
  • Publish AGOL items (NUTS0-3, LAU), set sharing, and run query/render smoke tests

Deliverables

Data Products

  • OSM boundary GeoJSON outputs staged for client processing (country + admin level organization)
  • Processing handoff describing the FGDB schema, attribution approach, and QA/QC checks for client execution
  • Client-produced outputs (Phases 4-6): FGDB feature classes and AGOL hosted feature layers

Implementation Assets

  • Terraform configuration for AWS resources and repeatable deployment
  • Pipeline orchestration scripts with checkpoint/restart logic and S3 sync
  • ArcGIS Pro notebooks/scripts (handoff) for client execution: import, attribution, QA/QC, and publishing

Acceptance Criteria

  • Phases 1-3 complete: infrastructure deployable and OSM → GeoJSON pipeline runs end-to-end with checkpointing and synced outputs
  • Handoff complete: client has documented procedures and scripts/notebooks to execute Phases 4-6
  • Overall outcome (client execution): client publishes hosted layers for NUTS0-NUTS3 and LAU, with issues triaged during the 30-day support window
