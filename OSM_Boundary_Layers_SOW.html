Executive Summary

This engagement delivers a repeatable, restartable pipeline that converts the planet OSM PBF into administrative boundary GeoJSON outputs, then transforms those outputs into an ArcGIS Pro file geodatabase (FGDB) and publishes separate ArcGIS Online hosted feature layers suitable for web mapping, analysis, and downstream application integration. The work is organized into two phases: (1) Infrastructure setup and GIS processing, and (2) 30 days of post‑delivery support.

Scope Overview

In Scope

  • AWS infrastructure as code for a high‑memory processing host, storage, and permissions
  • Planet OSM → GeoJSON boundary extraction split by country and administrative level
  • GeoJSON normalization (GeoJSONSeq .geojsonl → FeatureCollection .geojson) and optional chunking
  • ArcGIS Pro import to an FGDB per boundary level (NUTS0–3, LAU)
  • Hybrid attribution: OSM codes → Wikidata crosswalk → GISCO spatial fallback
  • QA/QC + finalization: geometry repair, dissolve by code, duplicates, metrics, validation
  • Publish to ArcGIS Online hosted feature layers with metadata and smoke tests

Out of Scope (unless added by change order)

  • Custom web app development beyond layer publication and basic usability checks
  • Ongoing monthly operations beyond the defined 30‑day support window
  • Third‑party licensing, ArcGIS Pro licensing, or ArcGIS Online credit purchases
  • Non‑Europe schemas outside the NUTS/LAU target model (additional regions can be scoped)
  • Long‑term data governance program design (policies, stewards, committees)

Important Assumptions

The contractor will require access to an AWS account for provisioning and an ArcGIS environment (ArcGIS Pro and ArcGIS Online organization) for publishing. A single reference vintage year for GISCO/NUTS/LAU will be selected and used consistently for attribution and validation.

High‑Level Implementation Plan

Step 1

Confirm inputs, naming, and reference datasets

6–10 hrs

Lock decisions that prevent rework later (file conventions, GISCO vintage, publishing titles, and field model).

  • Define input/output folder conventions and AGOL item naming
  • Select GISCO/NUTS/LAU vintage year and obtain reference boundaries
  • Confirm minimum field schema (IDs, names, country, provenance, confidence)
Step 2

Infrastructure setup (AWS, security, cost controls)

18–28 hrs

Provision a repeatable environment sized for planet‑scale OSM processing with safe defaults.

  • Terraform for VPC/Security Group, EC2 (memory‑optimized), EBS, S3, IAM role/policies
  • Bootstrap script to install osmium, Python deps, and attach/mount data volume
  • Operational guardrails (lifecycle cleanup, teardown guidance)
Step 3

Planet OSM → GeoJSON boundary pipeline (restartable)

40–70 hrs

Implement a checkpointed pipeline that can resume across interruptions and sync outputs continuously.

  • Filter administrative boundary relations and extract country polygons
  • Per‑country extraction and per‑level exports (GeoJSONSeq .geojsonl)
  • Orchestrator with checkpoint.json, logging, retries, and periodic S3 sync
Step 4

Normalize & stage GeoJSON for ArcGIS Pro

16–28 hrs

Convert GeoJSONSeq to ArcGIS‑importable FeatureCollections and optionally chunk/merge for large countries.

  • .geojsonl → .geojson FeatureCollection conversion
  • Optional chunking for very large files and repeatable merge strategy
  • Documented staging layout for import runs
Step 5

ArcGIS Pro FGDB build + hybrid NUTS/LAU attribution

46–78 hrs

Create clean, queryable feature classes per level and assign official codes with confidence tracking.

  • ArcGIS Pro import via JSON To Features into FGDB (one feature class per level)
  • Attribution priority: OSM refs (ref:nuts/ref:lau) → Wikidata crosswalk → GISCO overlap match
  • Record method and match score; flag low‑confidence matches for review
Step 6

QA/QC, dissolve, publish to ArcGIS Online, and smoke tests

34–56 hrs

Finalize geometry and publish hosted layers with consistent metadata and baseline performance checks.

  • Repair geometry, multipart handling, deduplication, dissolve by code, compute area/perimeter
  • Validate coverage and counts vs GISCO and generate match statistics
  • Publish AGOL items (NUTS0–3, LAU), set sharing, and run query/render smoke tests

Deliverables

Data Products

  • FGDB workspace with feature classes: NUTS0, NUTS1, NUTS2, NUTS3, LAU
  • ArcGIS Online hosted feature layers (one item per level) with metadata and tags
  • Attribution audit fields: method, confidence score, and reference vintage year

Implementation Assets

  • Terraform configuration for AWS resources and repeatable deployment
  • Pipeline orchestration scripts with checkpoint/restart logic and S3 sync
  • ArcGIS Pro notebooks/scripts for import, attribution, QA/QC, and publishing

Acceptance Criteria

  • Hosted layers exist for NUTS0, NUTS1, NUTS2, NUTS3, and LAU in ArcGIS Online
  • Geometry is valid and layers render without errors at common web map scales
  • Minimum field schema is present (IDs, names, country, provenance/method, match score)
  • QA/QC summary produced (coverage counts, match statistics, and flagged low‑confidence cases)
